Reaching that gate required six live-only defects that appear only against a real model;
each is fixed in this record's tree:

1. the live path still read a removed `boot["integ_hash"]` and would have crashed;
2. `max_turns` was clamped to the adapter's own default of 12, silently overriding the
   SPEC §27 ceiling of 30 (now the adapter defaults to the system limits);
3. a negated marker in prose ("[[HIBIKI:BLOCKED]] is not applicable") was read as a real
   block, failing a complete delivery;
4. upstream deliverables were never staged into dependent Workspaces, so an INTEGRATE
   unit could not read the artifacts its objective named;
5. a Repair revision's Workspaces were never provisioned — the sandbox created them
   root-owned and empty, so the REPAIR Run reported `workspace_missing`;
6. task objectives described the whole pipeline per unit, so workers attempted later
   units' work and exhausted their turns instead of their own step.

M2 is therefore accepted for G1–G6. Remaining limits are recorded separately in
[`docs/M2-KNOWN-GAPS.md`](../M2-KNOWN-GAPS.md) — they are not §24.5 gate criteria.
