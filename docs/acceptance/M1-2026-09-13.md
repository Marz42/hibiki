### Adversarial review of the M1 surface (round 3)

A dedicated review pass over the M1 code found four P1 and five P2 defects; all are
fixed with regression tests in `tests/m1/test_m1_review_fixes.py` (commit `ef15221`):

| # | Severity | Finding | Fix |
| --- | --- | --- | --- |
| 1 | P1 | A confirmed stop released the workspace but left the Run `RUNNING`, so its credential could still run tools, publish and submit a PASS result | The stop finishes the Run (`CANCELLED`, occupancy released); the broker, publish and append paths refuse it, and a late result is history only |
| 2 | P1 | TOCTOU symlink escape: publish/append validated a path then re-opened it by name, so a concurrent writer could swap in a symlink (cross-Task read) | Bytes are read and hashed through one descriptor inside `WorkspacePaths`; a workspace owned by another Run or a revoked Run is refused |
| 3 | P1 | Any `artifact_refs` string became an `ArtifactRow` and then the Work Unit's `verified_artifact_hash`, so a fabricated hash looked like a verified delivery | Registration precedes the delivery check and only a content-backed reference (with `artifact_uri`) may become the verified delivery |
| 4 | P1 | Sandbox cancel/timeout could orphan the client process group when the cidfile was not ready (`_reap`/`killpg` were dead code) | Both paths go through `_stop_container`, killing the container or the client group and reaping it |
| 5 | P2 | `record_model_usage` had no authorization, no run binding and accepted negative counts | Internal-only, run-bound, `calls >= 1`, enforces the Contract-tightened ceiling; the adapter obeys the refusal |
| 6 | P2 | `RunExecutionSpec.wall_timeout_seconds` was never enforced | Bounds the worker loop and caps each model call (plus a stop cap) |
| 7 | P2 | An empty model completion was reported `COMPLETED`/`PASS` | Empty completion is `BLOCKED` |
| 8 | P2 | The conservative lost-run policy was dead code | Reconcile applies it; a Run that may have produced an effect blocks for a human |
| 9 | P2 | Dependency-result bytes were never counted towards the context budget | Counted via the dependency artifact's recorded size |

Review-verified clean: the `WorkspacePaths` dir_fd/`O_NOFOLLOW` walk, broker cross-run
and cross-task binding, the tool ceiling ∩ catalog, duplicate-sequence handling,
foreign-credential refusal on `get_run_input`/`get_run_context`, idempotent adapter
start and artifact republication, the publish crash window, sandbox hardening flags,
credential env filtering, and provider-key redaction with classified retries.

### Bugs found and fixed while writing these acceptance tests

1. A path that escapes the workspace, or a workspace that is not materialized, was
   recorded as `decision=ALLOW` with outcome `denied`; both are now explicit `DENY` rows
   (`path_escape` / `workspace_missing`) so the audit shows an unauthorized request
   rather than a failed one.
2. The adapter submitted a plain `fs.write` file digest as an artifact reference, and a
   model can also fabricate one; only a Core-registered artifact hash may become a
   delivery reference now, and `list_unbacked_artifacts` surfaces the rest.
3. The sandbox initially mounted a shared root, letting one Run read another Run's
   files; it now re-mounts the workspace from the Run's own frozen spec.
4. `atomic_write` created files as `0600`, which the uid-65534 sandbox could not read.

## 5. Known limits carried into M1

- **Rootless Docker is not available on this host** (no `uidmap`/`newuidmap`, Docker
  Desktop has no rootless mode), so the daemon is rootful inside its VM and the
  orchestrator is host-root-equivalent through the `docker` group; the Broker never
  mounts the Docker socket into a sandbox.
- The worker↔Core channel is an in-process `ApplicationService` handle with run-bound
  Internal credentials; the REST/MCP surface stays M3.
- The sandbox enforces wall-clock time orchestrator-side (Docker has no wall-clock flag).
- The fake provider used for the pre-credential smoke is a **provider** double only: the
  adapter speaks real HTTP, the Tool Broker and the Docker sandbox are the real ones.
- `ruff format --check` still reports pre-existing files that would be reformatted.
