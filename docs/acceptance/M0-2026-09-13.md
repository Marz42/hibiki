## 2. Repairs applied in this wave

### R8-1 — diagnose unknown schema state before migrating (was blocker M0-1)

- `hibiki/domain/errors.py`: added `SchemaStartupError` (`code = "schema_startup_refused"`).
- `hibiki/application/bootstrap.py`: `run_migrations()` now fingerprints the existing database
  **before** Alembic runs. An existing `schema_meta.schema_version` that differs from the expected
  value, or an `alembic_version` the current code does not know, refuses startup with a diagnostic
  naming both values (and the code's heads). A fresh database, or one with unrelated application
  tables, still migrates normally; a known older revision still upgrades to head.
- `hibiki/interfaces/cli/main.py`: startup refusal is reported as
  `hibiki: refusing to start: …` with exit code 2; domain errors raised by commands print
  `hibiki: <code>: <message>` on stderr with exit code 1 instead of a traceback; command failures
  keep their JSON result on stdout and add a one-line diagnostic on stderr.

Before/after on the same inputs (`schema-refusal.log`):

| Case | Before R8-1 | After R8-1 |
| --- | --- | --- |
| `schema_meta= m99_future`, no `alembic_version` | `sqlalchemy.exc.OperationalError: table schema_meta already exists` | `refusing to start: schema version unknown … expected 'm0'` (exit 2) |
| at head, `schema_version = m99_future` | unhandled `RuntimeError` traceback | same diagnostic, exit 2 |
| `alembic_version = 9999_from_the_future` | DDL failure | `database reports Alembic revision '9999_from_the_future' …` (exit 2) |
| quickstart `hibiki --data-dir <new>` | worked | still works (exit 0) |
| `get-task --task-id <missing>` | `NotFoundError` traceback | `hibiki: task_not_found: task … not found` (exit 1) |

### R8-2 — make the 100-seed measurement actually exercise the protected paths (was blocker M0-2)

- `tests/property/test_random_schedule.py`: each trajectory now runs a mandatory checkpoint that
  drives the full legal path (submit → human approval → duplicate approval replay → User-Agent
  approval refusal → activate → dispatch → worker result) plus a duplicate and an illegal approval
  injection, and then a ~190-step state-aware random walk (≈85 % state-legal progress, ≈12 %
  illegal input) instead of a uniform pick that almost never satisfied a guard.
- Post-terminal inputs no longer cut the step budget short: the trajectory keeps submitting
  illegal/duplicate/late inputs to a terminal task until 200 inputs are reached.
- `test_100_fixed_seeds` now asserts the coverage itself: every seed dispatches ≥1 Run, every seed
  submits ≥1 worker result, ≥95/100 end in a terminal state, and no target hash is ever formally
  approved twice (verified against the `decisions` table, not a local counter).

Before/after on the same seeds:

| Metric | Before R8-2 | After R8-2 |
| --- | --- | --- |
| trajectories reaching `EXECUTING` | 24/100 | 100/100 |
| trajectories dispatching a Run | 0/100 | 100/100 (176 dispatches) |
| trajectories with a worker result | 0/100 | 100/100 (176 submissions) |
| trajectories reaching a terminal state | 0/100 | 98/100 (2 still `EXECUTING`) |
| inputs per trajectory | 202 uniform | 200–211 mixed, state-aware |

## 3. Rounds 1–7 status

All previously documented blockers (R2–R7) remain covered by their regression tests, which pass in
this run: adapter `RLock` + revoke re-check before register, revoke preserving stubborn-writer

## 4. Freeze decision

- **M0 control invariants: PASS.** The schema is frozen at the round-8 commit that contains this
  record and the evidence directory; that commit is the first tree on which all of §24.3 passes
  with the coverage above.
- Freezing means M0's schema and authorization protocol are the baseline for M1. Any later change
  to schema, state machine, guard matrix or evidence semantics invalidates this record and
  requires a new §24.3 measurement.
- M1 may now start: one real API adapter, Tool Broker, sandbox/Workspace/Artifact publishing,
  ContextManifest append, real process stop, H-022–H-032, 6 real runs with ≥5 inside budget, and
  Pause/Cancel within 15 s.

- the CLI cannot complete a task end to end: `submit-result` is Internal-only by design

  tests for acceptance flows;
- `ruff format --check` reports 10 files that would be reformatted — pre-existing, no behavioural
  impact, deliberately left out of a freeze-boundary change.
